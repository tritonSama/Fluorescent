## 4. Adversarial Challenge Report

### Overall Risk Assessment: **CRITICAL**

### Challenges

#### Challenge 1: Pointer Dereference Crash Attack
- **Assumption Challenged**: That `SharedFrameBuffer.ptrAddress()` returns a safe native memory address.
- **Attack Scenario**:
  ```dart
  final sharedBuf = SharedFrameBuffer(sizeBytes: 1024);
  final ptr = ffi.Pointer<ffi.Uint8>.fromAddress(sharedBuf.ptrAddress());
  ptr.value = 0x42;
  ```
- **Blast Radius**: `STATUS_ACCESS_VIOLATION` (0xC0000005) crash of the Flutter Desktop process.
- **Mitigation**: Return genuine native heap address from Rust allocator, never a fake synthetic integer.

#### Challenge 2: Memory Leak Under 60 FPS Allocation Loop
- **Assumption Challenged**: That native buffer allocations are reclaimed by Dart GC.
- **Attack Scenario**: Allocate 1MB in a 60 FPS loop for 60 seconds (3,600 allocations).
- **Blast Radius**: Leaks >3.6 GB of unmanaged RAM, triggering OOM abort.
- **Mitigation**: Bind `wire__crate__api__engine__free_engine_buffer` to a Dart `NativeFinalizer`.

#### Challenge 3: Subsystem Desynchronization
- **Assumption Challenged**: That `startEngine()` in Dart transitions the native engine into running state.
- **Attack Scenario**: Call `startEngine()` in Dart, then query native C-ABI directly.
- **Blast Radius**: Native `ENGINE_ALLOCATOR` remains uninitialized (`None`), while Dart claims `isInitialized: true`.
- **Mitigation**: Call `platform.startEngineSyncRaw()` inside `crateApiEngineStartEngine()`.
