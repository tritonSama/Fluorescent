## 2. Logic Chain

1. **RenderGraph Architecture**:
   - *Observation*: Current WebGPU rendering in `webgpu_bridge.js` (lines 95-115) and Vulkan rendering in `fluorescent_vulkan.cpp` (lines 385-415) hardcode a single render pass with static clear colors and fixed pipeline targets.
   - *Inference*: To satisfy Requirement R2 ("Implement a data-driven `RenderGraph` (parsing JSON/YAML) to replace hardcoded WebGPU passes"), a declarative DAG-based `RenderGraph` must be introduced in `fluorescent_core`.
   - *Requirements*:
     - The RenderGraph requires two core resource primitives: `AttachmentDescriptor` (name, format, size/scale, loadOp, storeOp, clearValue) and `RenderPassDescriptor` (name, type, color/depth attachments, inputs, dependencies).
     - The graph must support JSON/YAML deserialization (`RenderGraph.fromJson` / `RenderGraph.fromYaml`), DAG cycle detection, and topological sorting to establish deterministic pass execution order.
     - The graph must provide an execution interface consumable by `RenderingServer` or `fluorescent_webgpu`.

2. **Asset Pipeline CLI (`asset_pipeline`)**:
   - *Observation*: `tools/asset_pipeline` is empty (.gitkeep only), no CLI entry point exists, and no test assets exist.
   - *Inference*: A standalone Dart CLI package (`tools/asset_pipeline/pubspec.yaml` and `tools/asset_pipeline/bin/asset_pipeline.dart`) must be implemented to fulfill R2 and Acceptance Criterion 2.
   - *Requirements*:
     - CLI options: `--input` / `--gltf`, `--shader`, `--output`, `--compress`.
     - Ingestion: Pure-Dart parser for `.gltf` (extracting positions, normals, UVs, indices) and `.wgsl` files.
     - Packaging: Binary `.fworld` serializer that writes a magic header (`FWLD`), manifest/metadata chunk, binary geometry chunks, and shader bytecode/text chunks.
     - Compression: Standard library `gzip.encode` or `zlib.encode` from `dart:io` provides zero-dependency binary compression.
     - Runtime Loader: Update `World3D.load(String path)` in `fluorescent_core` to deserialize `.fworld` binaries.

3. **Shader Toolchain (Pillar 4)**:
   - *Observation*: Neither `cargo` nor `cmake` is installed on the host, and no pre-built `naga.dll` exists. Requirement R4 specifies integrating Naga/SPIRV-Cross via FFI, with acceptance criterion requiring `asset_pipeline` to compile `.wgsl` into binary output under `integrity mode: demo`.
   - *Inference*: Relying strictly on a hard dynamic library load would fail immediately with `DllNotFoundException`. The shader toolchain must follow a resilient dual-mode architecture:
     - `ShaderTranspiler` interface with `NagaFfiTranspiler` attempting `DynamicLibrary.open` with full C-ABI signatures.
     - Graceful fallback to `DemoShaderTranspiler` (or pure-Dart transpiler) when native libraries are not present on the host.
     - WGSL -> SPIR-V: Generates valid SPIR-V binary words (magic `0x07230203`, version, capabilities, and OpEntryPoint) leveraging verified SPIR-V bytecode from `tools/generate_shaders.py`.
     - WGSL -> MSL: Translates WGSL shader functions and qualifiers (`@vertex` -> `vertex`, `@fragment` -> `fragment`, `@builtin(position)` -> `[[position]]`, `vec4<f32>` -> `float4`) into valid Metal Shading Language source code.
     - Multi-target shader bundle: Stores original WGSL, compiled SPIR-V, and generated MSL into the `.fworld` container.

## 3. Caveats

1. **Native Dynamic Libraries**: Because Cargo and CMake are not available on the execution host, native compilation of `naga` or `spirv-cross` C-libraries is not possible directly during tests on this machine. The FFI layer must provide mock/demo dynamic library loading or clean fallback behavior.
2. **YAML Dependency**: The `yaml` package is not currently in `fluorescent_core/pubspec.yaml`. However, standard JSON (`dart:convert`) is 100% built-in, and JSON is a strict subset of YAML 1.2. Supporting JSON natively (with optional `package:yaml` if added to dependencies) satisfies the requirement cleanly without breaking dependency locks.
3. **WebGPU Platform Support**: In `fluorescent_webgpu`, actual execution of WebGPU requires a browser supporting WebGPU (Chrome 113+). Automated tests for `RenderGraph` in CLI/unit test runners must run on Dart VM without requiring a browser window.

### 4.2 Detailed Specifications

#### A. Data-Driven RenderGraph Design
- **AttachmentDescriptor**:
  - `name`: String (e.g. `sceneColor`, `shadowMap`, `depthStencil`, `backbuffer`)
  - `type`: `color` | `depth` | `storage`
  - `format`: `rgba8unorm` | `rgba16float` | `depth24plus` | `depth32float`
  - `size`: `[width, height]` or `scale`: `[scaleX, scaleY]`
  - `loadOp`: `clear` | `load` | `dontCare`
  - `storeOp`: `store` | `discard`
  - `clearColor`: `[r, g, b, a]` (default `[0.0, 0.0, 0.0, 1.0]`)
  - `clearDepth`: `double` (default `1.0`)
- **RenderPassDescriptor**:
  - `name`: String (e.g. `shadow_pass`, `gbuffer_pass`, `lighting_pass`, `post_process`)
  - `type`: `raster` | `compute`
  - `colorAttachments`: List of attachment names/configs
  - `depthStencilAttachment`: Optional depth attachment name
  - `inputs`: List of read attachment names
  - `dependencies`: List of preceding pass names
  - `shader`: Shader module reference
- **Compilation & Validation Algorithm**:
  1. Build adjacency list `Map<String, Set<String>>`.
  2. For every pass, verify input attachments exist; if an attachment is written by pass A and read by pass B, add edge `A -> B`.
  3. Detect cycles using depth-first search (throw descriptive `RenderGraphCycleException` if detected).
  4. Perform topological sort (Kahn's algorithm) to compute `executionOrder: List<RenderPassDescriptor>`.
  5. Dead pass elimination: any pass whose outputs are neither read by subsequent passes nor connected to the backbuffer is pruned.

#### B. `.fworld` Binary Format Specification
- **File Layout**:
  ```
  [0x00..0x03] Magic Bytes: 0x46, 0x57, 0x4C, 0x44 ("FWLD")
  [0x04..0x07] Format Version: uint32 (e.g., 1)
  [0x08..0x0B] Compression Type: uint32 (0 = uncompressed, 1 = gzip, 2 = zlib)
  [0x0C..0x0F] Uncompressed Payload Size: uint32
  [0x10..End ] Compressed Payload Data:
      ├── Table of Contents (TOC) / Header:
      │   ├── Manifest JSON (metadata, scene nodes, hierarchy)
      │   ├── Number of Meshes & Offsets
      │   └── Number of Shaders & Offsets
      ├── Mesh Chunks:
      │   ├── Vertex Count, Index Count
      │   ├── Position Buffer (Float32List)
      │   ├── Normal Buffer (Float32List)
      │   ├── UV Buffer (Float32List)
      │   └── Index Buffer (Uint16List / Uint32List)
      └── Shader Chunks:
          ├── Shader Name
          ├── WGSL Code String
          ├── MSL Code String
          └── SPIR-V Bytecode (Uint32List / Uint8List)
  ```

#### C. Shader Toolchain FFI & Fallback
- `ShaderTranspiler` interface:
  ```dart
  abstract class ShaderTranspiler {
    ShaderBundle transpileWgsl({
      required String wgslSource,
      String vertexEntryPoint = 'vertexMain',
      String fragmentEntryPoint = 'fragmentMain',
    });
  }
  ```
- `NagaFfiTranspiler`: Defines FFI functions for `naga_compile_wgsl_to_spirv` and `naga_compile_wgsl_to_msl`. If `DynamicLibrary.open` fails (library not found), falls back automatically to `DemoShaderTranspiler`.
- `DemoShaderTranspiler`:
  - Parses WGSL tokens to validate entry points.
  - Generates SPIR-V binary starting with `0x07230203` words (incorporating standard SPIR-V bytecodes from `tools/generate_shaders.py`).
  - Generates valid MSL string with `#include <metal_stdlib>`, translating entry points and attributes.
  - Returns `ShaderBundle(wgsl: ..., spirv: ..., msl: ...)`.

## 5. Verification Method

To independently verify the implementation once built:

1. **RenderGraph Unit Tests**:
   - Command: `flutter test packages/fluorescent_core/test/render_graph_test.dart`
   - Checks:
     - Validates JSON parsing of multi-pass configurations.
     - Confirms topological sort produces correct pass order (`shadow_pass` before `lighting_pass`, etc.).
     - Confirms cycle detection throws `RenderGraphCycleException` on cyclic dependencies.
     - Confirms backbuffer dead-pass elimination.
2. **Asset Pipeline CLI Tests**:
   - Command: `dart test tools/asset_pipeline/test/asset_pipeline_test.dart`
   - Command: `dart run tools/asset_pipeline/bin/asset_pipeline.dart --gltf test_assets/cube.gltf --shader test_assets/basic.wgsl --output output.fworld`
   - Checks:
     - Generates valid `.fworld` binary file.
     - Verifies file starts with magic bytes `FWLD`.
     - Decompresses and verifies geometry matches input `.gltf`.
     - Verifies bundled shaders contain valid SPIR-V (magic `0x07230203`) and MSL code.
3. **Invalidation Conditions**:
   - Any test failure on Dart 3.13 / Flutter 3.47.
   - Throwing `DllNotFoundException` in environments without Rust/Cargo installed.
   - `.fworld` files failing magic byte verification or failing decompression.
